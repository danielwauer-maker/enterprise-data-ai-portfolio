# Roblox Growth Copilot — Architecture Baseline

## Goal
Build a thin decision-intelligence layer above Roblox analytics rather than duplicating Roblox Analytics.

## Logical architecture

Roblox Analytics / Open Cloud
-> Connection & Query Adapter
-> Metric Normalization
-> PostgreSQL History
-> Deterministic Decision Engine
-> Evidence Bundle
-> AI Product Analyst
-> Priorities / Investigation / Experiment Copilot / Weekly Brief

## Frontend
- Next.js + TypeScript
- Product-led onboarding
- Minimal health view
- Decision-first UI

## Backend
- FastAPI
- Pydantic contracts
- Roblox analytics adapter
- decision/rule engine
- AI orchestration layer
- scheduled refresh / weekly brief jobs

## Data model — initial
- accounts
- users
- studios
- experiences
- connections
- metric_snapshots
- metric_segments
- decision_runs
- priority_findings
- evidence_items
- experiment_proposals
- reports
- subscriptions
- audit_events

## AI grounding contract
The LLM never calculates authoritative metrics. It receives a structured evidence bundle generated by deterministic code. Each recommendation contains:
- finding type
- affected KPI
- current value
- baseline/comparison value
- affected segment
- impact score
- confidence score
- supporting evidence IDs
- allowed recommendation class

If evidence is insufficient, output must be `INSUFFICIENT_EVIDENCE` rather than fabricate a cause.

## Security baseline
- least-privilege Roblox access
- encrypted secrets / no plaintext keys in logs
- disconnect and deletion workflow
- audit trail for data access and generated recommendations
- tenant isolation
- explicit retention policy

## V1 deployment target
Containerized web/API stack with managed PostgreSQL and standard observability. Infrastructure choice remains open until R7/R10 to avoid premature lock-in.
